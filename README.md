# OrderFlow Trinity: 바이낸스 USDⓈ-M 선물 자동매매 봇

RSI, MACD, 이동평균 크로스, 볼린저 터치 같은 흔한 조건은 쓰지 않습니다.
대신 바이낸스 캔들에 들어 있는 **테이커(시장가) 체결량**으로 오더플로우를 읽습니다.
보는 질문은 하나입니다: *"누가 시장가로 공격했고, 가격은 거기에 어떻게 반응했나?"*
진입 횟수를 늘리려고 거래대금 상위 15개 코인(5분봉)을 동시에 감시합니다.

> ⚠️ **수익을 보장하지 않습니다.** 이 저장소를 만든 환경에서는 바이낸스 접속이 막혀 있어서
> **실제 시세로 백테스트하지 못했습니다.** 코드가 버그 없이 돌아가는지만 합성 데이터로 테스트했습니다.
> 반드시 아래 순서로 직접 검증하세요: `backtest → --optimize(OOS 검증) → paper → testnet → 소액 live`.

## 진입 셋업 3종

| 셋업 | 유형 | 조건 (마감봉 기준, 다음 봉 시가에 진입) |
|---|---|---|
| **ABSORB** (흡수 반전) | 평균회귀 | 가격이 rolling VWAP 에서 2σ 이상 이탈 + 거래량 z-score 급증 + **시장가 매도가 압도적인데 캔들은 위쪽에서 마감**. 지정가 매수가 물량을 다 받아냈다는 뜻이라 매도 소진으로 보고 롱 진입 (숏은 반대) |
| **TRAP** (갇힌 돌파) | 역추세 | 직전 봉이 24봉 고점을 **시장가 매수 우위·거래량 증가**로 돌파했는데, 이번 봉이 돌파 레벨 아래로 되돌아와 마감하고 매도 우위로 바뀜. 추격 매수자들이 물렸다고 보고 그들의 손절 물량을 노려 숏 (롱은 반대) |
| **SQUEEZE** (델타 확인 압축 돌파) | 추세 | 밴드폭이 최근 120봉 중 하위 20% (변동성 압축) → **테이커 매수 우위 + 거래량 증가 + 고가 근처 마감**으로 24봉 고점 돌파. 가짜 돌파를 델타로 걸러냄 |

공통 필터
- **펀딩비 과열 필터**: 펀딩비가 +0.05% 를 넘으면 롱 금지, -0.05% 아래면 숏 금지 (쏠린 쪽 진입 회피)
- **최소 손절폭 0.4%**: 5분봉에서는 손절이 너무 좁으면 왕복 수수료(약 0.14%)가 손익을 다 먹어버림
- 청산: ATR 기반 손절/익절, `max_hold_bars`(기본 36봉 = 3시간) 시간 손절

## 리스크 관리
- 사이징: 손절 시 계좌의 `risk_per_trade`(기본 0.5%)만 잃도록 수량 계산
- 동시 최대 포지션 4개, 심볼당 1개, 격리 마진
- 일일 손실 3% 도달 시 당일 신규 진입 중단
- 봇 감시 손절(마크 가격 기준) + 거래소 측 비상 STOP_MARKET (봇이 꺼져도 보호)
- 상태를 `state_<mode>.json` 에 저장해서 재시작해도 포지션을 이어서 관리

## 1단계: 백테스트 (필수)

```bash
python backtest.py --days 120                         # 거래대금 상위 15개, 120일
python backtest.py --symbols BTCUSDT,ETHUSDT,SOLUSDT --days 180
python backtest.py --days 180 --optimize              # 앞 70% 로 파라미터 탐색, 뒤 30% 로 검증
```

- 출력: 거래수, 하루 평균 진입 수, 승률, 평균 R, Profit Factor, 총수익률, 최대낙폭, 셋업별/심볼별 성과
- 거래 내역은 `backtest_trades.csv` 로 저장됨
- 성과가 나쁜 셋업은 config 에서 `*_enabled: false` 로 끄세요
- API 가 막힌 지역이면 [data.binance.vision](https://data.binance.vision) 에서 `futures/um/monthly/klines` CSV 를 받아
  `data/vision/` 에 풀고 `--vision-dir data/vision` 옵션을 쓰면 됩니다

**판단 기준(권장)**: OOS 구간에서 PF ≥ 1.2, 거래 200회 이상, 최대낙폭이 감당 가능한 수준.
IS 에서만 좋고 OOS 에서 무너지면 과최적화입니다. 이 경우 실전에 쓰면 안 됩니다.

## 한계 (꼭 읽으세요)
- 백테스트는 봉 내부 가격 경로를 모르기 때문에 손절과 익절이 같은 봉에 닿으면 손절로 처리합니다(보수적 가정). 펀딩비 지불/수취는 반영하지 않습니다
- 백테스트의 동시 포지션 제한은 근사치입니다. 심볼별로 먼저 시뮬레이션한 뒤 포트폴리오에서 거르는 방식이라 그렇습니다
- 테이커 매수량은 kline 집계치라서 진짜 호가창·체결 틱 수준의 오더플로우보다 정밀도가 낮습니다
- 바이낸스는 조건부 주문(STOP_MARKET)을 Algo Order API 로 옮기는 중입니다. 비상 손절 등록이 실패하면 로그에 경고가 남고, 봇의 자체 손절 감시는 계속 동작합니다
- 투자 판단과 손실 책임은 사용자에게 있습니다
